# 弘文社 在庫管理アプリ（Phase2）

商品マスタ登録 + 在庫一覧・増減 + 入出庫履歴記録 ができるところまでのMVPです。
予定管理・引き継ぎアプリと同じFirebaseプロジェクトを使い回す前提で作っています。

## できること（Phase1）
- 商品登録（商品名・分類・単位・現在庫数・在庫僅少ライン・備考）
- 在庫一覧表示（分類での絞り込み／商品名検索）
- 在庫僅少の商品を赤枠で強調表示
- 商品の編集・削除
- メンバー個別ログイン（予定管理アプリと同じ `名前@koubunsha.com` 形式）

## できること（Phase2で追加）
- 各商品に「入出庫」ボタンを設置し、数量・区分（入庫／出庫）・備考を記録
- 記録と同時に現在庫数を更新（Firestoreトランザクションで整合性を担保）
- 現在庫数を超える出庫はエラーで防止
- 「入出庫履歴」タブで、誰が・いつ・何を・何個動かしたかを新しい順に一覧表示（商品名で検索可）
- 商品に「商品コード」「売価」を追加登録可能
- エクセル／CSVファイルからの商品一括登録（プレビュー確認してから登録）
- 商品ごとのQRコード発行（個別印刷／全商品または絞り込み後の一括ラベル印刷）
- 「伝票・検品」タブで出荷伝票・入荷伝票を作成
  - 取引先・品目（商品と数量）を登録して伝票を発行
  - 伝票を印刷（A4想定の伝票レイアウト）
  - 検品モードで実際の確認数量にチェック・修正し、「検品完了」で在庫に自動反映
  - 反映内容は入出庫履歴にも「伝票番号」付きで記録される
- 履歴・伝票データは新規コレクション（`inventory_movements` / `inventory_slips`）に保存（既存の在庫一覧には影響なし）

## QRコードの読み取りについて（Phase3への準備）
QRコードには商品のドキュメントIDをそのまま埋め込んでいます。次のPhase3で
スマホカメラでの読み取りに対応する際は、読み取った値でそのまま商品を検索し、
「入出庫」モーダルや検品画面を自動で開く形にする予定です。

## セットアップ

1. `firebase-config.js` を開き、`firebaseConfig` の中身を **予定管理アプリと同じ値** に書き換える
   （Firebaseコンソール → プロジェクトの設定 → 全般 → マイアプリ）
2. Firestoreのセキュリティルールに、このアプリ用のコレクションへの読み書き許可を追加する
   （ログイン済みユーザーのみ許可する例）
   ```
   match /inventory_products/{docId} {
     allow read, write: if request.auth != null;
   }
   match /inventory_movements/{docId} {
     allow read, write: if request.auth != null;
   }
   match /inventory_slips/{docId} {
     allow read, write: if request.auth != null;
   }
   ```
   ※ Phase1から引き続きお使いの場合は、`inventory_movements` と `inventory_slips` の行を追加するだけでOKです。
3. GitHubリポジトリを新規作成し、このフォルダの中身をpush
4. GitHub Pagesを有効化（Settings → Pages → mainブランチ）
5. メンバーのログインアカウント（`名前@koubunsha.com`）は予定管理アプリで
   すでに作成済みのものをそのまま使えます。新規メンバー分だけ追加してください。

## 商品カタログの登録について
弘文社様のオンラインカタログ（kobunsha.jp）はログインが必要な会員制サイトのため、
外部から自動取得することができませんでした。エクセル一括登録機能を使って、
カタログのExcel/CSVデータやサイト保存ファイルをいただき次第、まとめて登録します。
