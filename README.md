# 弘文社 在庫管理アプリ（Phase2）

商品マスタ登録 + 在庫一覧・増減 + 入出庫履歴記録 ができるところまでのMVPです。
予定管理・引き継ぎアプリと同じFirebaseプロジェクトを使い回す前提で作っています。

## できること（Phase1）
- 商品登録（商品名・分類・単位・現在庫数・在庫僅少ライン・備考）
- 在庫一覧表示（分類での絞り込み／商品名検索）
- 在庫僅少の商品を赤枠で強調表示
- 商品の編集・削除
- メンバー個別ログイン（予定管理アプリと同じ `名前@koubunsha.com` 形式）

## できること（Phase2で追加）
- 各商品に「入出庫」ボタンを設置し、数量・区分（入庫／出庫）・備考を記録
- 記録と同時に現在庫数を更新（Firestoreトランザクションで整合性を担保）
- 現在庫数を超える出庫はエラーで防止
- 「入出庫履歴」タブで、誰が・いつ・何を・何個動かしたかを新しい順に一覧表示（商品名で検索可）
- 商品に「商品コード」「売価」を追加登録可能
- エクセル／CSVファイルからの商品一括登録（プレビュー確認してから登録）
- 商品ごとのQRコード発行（個別印刷／全商品または絞り込み後の一括ラベル印刷）
- 「伝票・検品」タブで出荷伝票・入荷伝票を作成
  - 取引先・品目（商品と数量）を登録して伝票を発行
  - 伝票を印刷（A4想定の伝票レイアウト）
  - 検品モードで実際の確認数量にチェック・修正し、「検品完了」で在庫に自動反映
  - 反映内容は入出庫履歴にも「伝票番号」付きで記録される
- 履歴・伝票データは新規コレクション（`inventory_movements` / `inventory_slips`）に保存（既存の在庫一覧には影響なし）

## できること（Phase3で追加）
- スマホ・PCのカメラを使ったQRコード読み取りに対応（追加アプリ不要、ブラウザだけで動作）
- 在庫一覧・伝票一覧の「📷 スキャン」ボタンから、商品QRなら入出庫記録画面、伝票QRなら伝票詳細（検品）画面を自動で開く
- 伝票にもQRコードを付与（伝票詳細画面・印刷時に表示）。印刷した伝票をスキャンすれば、その伝票の検品画面に直接ジャンプできる（照合用）
- 検品画面の「📷 商品をスキャンして検品」ボタンで、実際の商品にQRをかざすだけで確認数量が自動加算される
- QRコードの中身は「その商品／伝票を直接開くURL」形式に変更（スマホの標準カメラアプリで読み取った場合もそのままアプリが開きます）
- カメラ利用には初回にブラウザから権限許可が必要です（GitHub PagesはHTTPS配信のため問題なく使えます）

## できること（Phase3.5で追加）
- **有線ハンディスキャナー対応**：在庫一覧・伝票一覧・検品画面に「🔫 ハンディスキャナー入力欄」を設置。スキャナーでの読み取り結果（キーボード入力として送られてくる）をそのまま認識し、カメラスキャンと同じ画面遷移を行います
- **検品時の連続スキャン＋警告**：検品画面でのスキャンはモーダルを閉じずに連続して読み取り続けます
  - 伝票に含まれない商品をスキャンした場合、または規定数を超えてスキャンした場合は、警告音（2回のビープ音）とスマホの振動で知らせます
  - 正しく検品できた場合は短い確認音を鳴らします（バイブは短め）
  - ※iPhoneの一部ブラウザでは振動（バイブ）に対応していない場合があります
- **商品コードでの品目検索**：伝票作成時、商品コードを入力してEnterを押すと、該当する商品を自動選択し、在庫数・売価を表示します（全商品リストから探す手間を削減）
- **入荷時のQRラベル一括印刷**：入荷伝票の検品完了後、その伝票に含まれる品目分のQRラベルをまとめて印刷できます（「🏷️ 受入QRラベルを印刷」ボタン）

## できること（Phase4で追加）
- **「発注管理」タブ**を新設。発注（購入発注）を作成し、ステータス（未発注／発注済み／入荷済み／キャンセル）で管理できます
  - 「＋ 発注を作成」から仕入先・品目（商品コード入力または商品名選択）・発注数量を登録
  - 発注詳細画面で「発注済みにする」→（仕入先へ発注後）「入荷完了として記録する」の順にステータスを進行
  - 「入荷完了として記録する」を押すと、実際に届いた数量を確認・修正のうえ、現在庫数に自動反映（入出庫履歴にも発注番号付きで記録）
  - 発注前であれば「発注をキャンセル」も可能
- **在庫僅少の自動通知**：在庫僅少ライン以下になった商品を検知すると、画面上部にトースト通知が自動で表示されます（Firestoreのリアルタイム更新をもとに、ページを開いたままでも自動で気づけます）
  - 「発注管理」タブを開くと、発注が必要な商品（僅少ライン以下かつ、まだ発注していない商品）が一覧で表示され、「まとめて発注案を作成」から発注案をワンタップで作成できます
  - タブに件数バッジも表示されるので、他のタブを見ているときも気づけます
  - 「🔔 ブラウザ通知を有効にする」を押すと、ブラウザ標準の通知（OS通知）でもお知らせします（このアプリのタブを開いたままにしている必要があります。閉じている間や別アプリを使っている間の通知には対応していません）
- 発注データは新規コレクション（`inventory_orders`）に保存

## セットアップ

1. `firebase-config.js` を開き、`firebaseConfig` の中身を **予定管理アプリと同じ値** に書き換える
   （Firebaseコンソール → プロジェクトの設定 → 全般 → マイアプリ）
2. Firestoreのセキュリティルールに、このアプリ用のコレクションへの読み書き許可を追加する
   （ログイン済みユーザーのみ許可する例）
   ```
   match /inventory_products/{docId} {
     allow read, write: if request.auth != null;
   }
   match /inventory_movements/{docId} {
     allow read, write: if request.auth != null;
   }
   match /inventory_slips/{docId} {
     allow read, write: if request.auth != null;
   }
   match /inventory_orders/{docId} {
     allow read, write: if request.auth != null;
   }
   ```
   ※ 以前から引き続きお使いの場合は、まだ追加していない行だけ追加すればOKです（Phase4からは `inventory_orders` が必要です）。
3. GitHubリポジトリを新規作成し、このフォルダの中身をpush
4. GitHub Pagesを有効化（Settings → Pages → mainブランチ）
5. メンバーのログインアカウント（`名前@koubunsha.com`）は予定管理アプリで
   すでに作成済みのものをそのまま使えます。新規メンバー分だけ追加してください。

## 商品カタログの登録について
弘文社様のオンラインカタログ（kobunsha.jp）はログインが必要な会員制サイトのため、
外部から自動取得することができませんでした。エクセル一括登録機能を使って、
カタログのExcel/CSVデータやサイト保存ファイルをいただき次第、まとめて登録します。
